# 优化路线

矩阵乘的全部难度只有一句话:**算得少、搬得多**。`2MNK` 次乘加对应 `(MK+KN+MN)` 个元素,K 越大,每个搬进来的字节就该被用得越多次。下面每一级都是在提高「一个字节被用几次」,直到把 tensor core 喂饱。

每一级后面标了它在**体检单**里对应哪个指标 —— 改完去看那一行有没有动,这是唯一可靠的验证方式。

## 0. 朴素:每个线程算一个 C 元素

```
for k in range(K):
    acc += A[m, k] * B[k, n]
```

`A` 的一行被 `N` 个线程各读一遍,`B` 的一列被 `M` 个线程各读一遍。算术强度只有 **0.25 flop/B**,离 roofline 拐点(5090 上约 128)差三个数量级。

**体检单**:判定「内存侧受限」,DRAM 接近 100%,Tensor pipe 是 0。

## 1. 合并访存 (memory coalescing)

同一个 warp 的 32 个线程如果访问的是连续地址,硬件把它们合成几个 128 B 的事务;如果是跨行的跳跃地址,就退化成 32 次独立事务,带宽直接掉到 1/32。

判断方法:让 `threadIdx.x` 走**最内层连续维**(行优先时是列)。写成 `C[ty][tx]` 而不是 `C[tx][ty]`。

**体检单**:L1/TEX 的「每请求 sector 数」。合并良好是 4,退化后会接近 32。

## 2. 共享内存分块 (tiling)

把 `A` 的 `BLOCK_M × BLOCK_K` 和 `B` 的 `BLOCK_K × BLOCK_N` 搬进共享内存,块内复用。每个元素被复用 `BLOCK_N`(或 `BLOCK_M`)次,算术强度提高同样的倍数。

```
        B tile
      ┌──────────┐
      │ BK × BN  │
      └──────────┘
 A tile      ↓
┌────────┐ ┌──────────┐
│ BM × BK│→│  C tile  │  一个 CTA 负责一块 C,沿 K 一段一段累加
└────────┘ └──────────┘
```

分块大小的天花板是共享内存:**5090(sm_120)每 block 上限 101376 字节**。`BLOCK_M×BLOCK_K + BLOCK_K×BLOCK_N` 个元素 × 元素字节 × 流水级数,超了就编不过。

**体检单**:L2 命中率上去、DRAM 下来;「共享内存 / block」那一行是你算的那个数。

## 3. 寄存器分块 (thread tiling)

共享内存也有带宽上限。让每个线程算 `TM × TN` 个输出而不是 1 个,把复用再往上提一层到寄存器 —— 共享内存读一次,寄存器里用 `TM × TN` 次。

代价是**寄存器压力**:累加器就占 `TM × TN` 个寄存器/线程。寄存器一多,每 SM 能并发的 block 就少,占用率掉下来。这是本级唯一的权衡。

**体检单**:「寄存器 / 线程」与「占用率 理论 / 实测」,尤其是**占用限制因子**那一格 —— 它会直接告诉你是寄存器还是共享内存卡住了。

## 4. 多级流水 (cp.async / num_stages)

到这里计算和访存还是串的:搬完一块 → 算一块 → 再搬。用 Ampere 的 `cp.async` 把「搬下一块」和「算当前块」重叠起来,开 N 级缓冲就能掩盖 N-1 段的延迟。

Triton 里这就是 `num_stages`,编译器会自动降到 `cp.async` 多级缓冲。共享内存用量按级数翻倍,所以第 2 级的上限在这里会被重新触碰。

**体检单**:stall 里的 `long_scoreboard`(等全局访存)应该明显下降。用 `klab ptx` 能直接数出 `cp.async` 的条数确认它真的生成了。

## 5. Tensor core (mma.sync / tl.dot)

前面四级都在解决「喂得够不够快」,这一级换「算得够不够快」:用矩阵指令替代标量 FMA。Ampere 是 `mma.sync`(同步,warp 级),Hopper 是 `wgmma`(异步,warpgroup 级),数据中心 Blackwell 是 `tcgen05`。

Triton 里写 `tl.dot(a, b)` 就够,降到哪条指令由目标架构决定。**`klab ptx` 是唯一能确认这件事的工具** —— 体检单只说 Tensor pipe 用了百分之多少,不说走的是哪条指令。

**体检单**:判定应该翻成「计算侧受限」,Tensor pipe ≥ 80%。到了这里 stall 主因变成 `math_pipe_throttle`,那是好事,说明 tensor core 在排队等着干活。

## 6. L2 swizzle(program 重排)

默认 `pid → (pid_m, pid_n)` 是按行铺的,同时在跑的那一批 block 横跨了很宽的一条,它们需要的 `B` 列几乎没有交集,L2 白白浪费。改成**按 group 分组**(连续的 `GROUP_M` 行块聚成一团再铺),同批 block 就会共享 tile。

```
按行铺(差)            按 group 铺(好)
0  1  2  3  4  5       0  2  4  6  8  10
6  7  8  9  10 11      1  3  5  7  9  11
```

**体检单**:L2 命中率。这一级对大矩阵收益明显,对已经放得进 L2 的小矩阵基本没有。

## 7. 尾波 (wave quantization)

一次能并发的 block 数 = `SM 数 × 每 SM 能放几个 block`。5090 有 170 个 SM,如果每 SM 放得下 2 个,一波就是 340 个。`4096/128 = 32×32 = 1024` 个 block,`1024 = 3×340 + 4` —— 最后一波只有 4 个 block 在跑,340 个槽位空了 336 个,整整浪费掉 1/4 波的时间。

改法:调分块让 block 数接近槽位数的整数倍,或者提高占用率让槽位变多。

**体检单**:「grid × block」那行的「几波/SM」。是小数且小于 2 就要留意;NCU 的建议原文里也会直接给出这一条的 `Est. Speedup`。

## 8. 换代:Hopper 与 Blackwell

| 特性 | 架构 | 换来什么 |
|---|---|---|
| `wgmma` | sm_90 | 异步 warpgroup MMA,发一条指令算一大块,发射开销摊薄 |
| TMA (`cp.async.bulk`) | sm_90 | 硬件做地址计算的批量异步拷贝,省掉一大堆整数指令 |
| warp specialization | sm_90 | 一部分 warp 专职搬数、一部分专职算,生产者消费者分离 |
| `tcgen05` + tmem | sm_100 | 第五代 tensor core,累加器搬到专用内存,不再挤寄存器 |

这几条 5090 都没有(sm_120 不是 sm_90 的超集),要练得换到 `modal-h100`。`meta.toml` 的 `requires.features` 会在跑之前就拦住不匹配的组合。

## 到哪一级算够

看两个数就行:**相对 torch 的倍数**和**对峰值的百分比**。cuBLAS 是几十人年调出来的,能到 0.9× 已经说明前六级都做对了;超过 1.0× 通常意味着你利用了某个 cuBLAS 不知道的先验(固定形状、特殊 layout、能融合的后续算子)。

低于 0.5× 的话,别急着往下一级走 —— 先用体检单的判定 + `klab ptx` 找出卡在第几级。
